# MA 16200 Study App 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the quiz into a tutor: a solution and problem type for every question, guided problems per lesson, a Today plan, a readiness panel and attempt history, on top of fixes for the eight review defects.

**Architecture:** The app stays a static Vite + React + TypeScript site. Pure functions in `src/engine/` decide what to show, `src/storage/` holds progress behind `ProgressStore`, and `src/ui/` renders. New behaviour follows that split: each feature is a pure engine function with unit tests, a storage addition covered by the shared contract tests, and a thin component. Content is JSON under `content/`, produced by subagents and checked by a blind second pass.

**Tech Stack:** TypeScript 5.9, React 19, React Router 7, Vite 7, Vitest 4 with Testing Library, Dexie 4 (IndexedDB), ts-fsrs 6, zod 4, KaTeX via react-markdown.

**Spec:** `docs/superpowers/specs/2026-11-10-study-app-2.0-design.md`

## Global Constraints

- No backend, no sign-in, no new runtime dependency. New dev dependencies are allowed only in Task 1 and are pinned to exact versions, as every dependency in `package.json` is.
- Exports stay at snapshot version 1. Every new export field is optional.
- Attempts are not migrated. Mastery constants are unchanged: no score until 3 attempts, recency weight 0.3, weak below 0.7.
- A question without `typeIds` shows no type features and must never cause an error. This holds until Task 28.
- UI code reads time and randomness from `useNow()` and `useRng()`, never `Date.now()` or `Math.random()`.
- All student-facing text and math renders through `src/ui/Markdown.tsx`.
- Copy fixed by the spec is used verbatim: "Check your understanding", "Try a similar question", "Past attempts", "Practise this type", "Done for today", "up to twelve questions".
- Before every commit: `pnpm lint` (from Task 1 on), `pnpm typecheck` and `pnpm test` all pass.
- Tests are written first and seen to fail before the code that passes them.
- Commit messages are one imperative sentence in the style of `git log`, ending with the session's co-author line.
- Work happens on branch `study-app-2.0`. Nothing is deployed by this plan; the owner runs `pnpm site:deploy`.
- Bulk content drafting runs on a cheaper-model subagent; checking runs on a stronger model in a fresh context that does not see the draft.

## Review Focus

1. **A stored session the app no longer understands.** A session in `localStorage` with an old shape, or naming an exam that was removed. Expected: the Exams page and the exam page offer Discard and never crash. Test in Task 9.
2. **History that refers to removed content.** Attempts, session records or guided results whose question, exam or problem id is no longer in `content/`. Expected: mastery, the Today plan, the backfill, Past attempts and results skip them silently. Tests in Tasks 14, 15 and 16.
3. **An export from before 2.0, or a hand-edited one.** No `sessions` or `guided` field; or a session record naming an unknown exam. Expected: it imports, history is rebuilt from attempts, unknown records are ignored. Tests in Tasks 5 and 14.
4. **Partly tagged content.** A question with no `typeIds`, a type with no questions, a lesson with no guided problems, an exam range with no tagged question. Expected: the type features are simply absent and the Today plan still lists what it can. Tests in Tasks 18, 20 and 25.
5. **The edge of the day.** An answer at 23:59 local time yesterday and one at 00:01 today, including across a daylight-saving change. Expected: only the second counts toward today's plan. Test in Task 20.
