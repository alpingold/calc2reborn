# MA 16200 Study App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static web app that follows Dr. Chen's MA 16200 lesson order, drills real past-exam questions and concept cards, schedules reviews with FSRS, and shows per-lesson weakness.

**Architecture:** Vite + React + TypeScript single-page app. Content is JSON under `content/`, bundled at build time and validated by tests. Progress lives behind a `ProgressStore` interface with Dexie (IndexedDB) and in-memory implementations. A pure `engine/` module holds scheduling, mastery, and selection logic with no React or storage dependencies. Node scripts under `scripts/` fetch, render, and crop exam PDFs.

**Tech Stack:** pnpm; react 19.3.1, react-dom 19.3.1, react-router 7.18.5; vite 7.3.7, @vitejs/plugin-react 6.2.1, typescript 5.9.3; vitest 4.1.12, jsdom 31.0.0, @testing-library/react 16.3.3, @testing-library/jest-dom 7.0.1, @testing-library/user-event 14.6.8; ts-fsrs 6.0.0; dexie 4.4.7, fake-indexeddb 6.2.7; katex 0.19.1, react-markdown 10.1.0, remark-math 6.0.0, rehype-katex 7.0.1; zod 4.6.7; scripts: tsx 4.23.15, pdfjs-dist 6.5.438, @napi-rs/canvas 1.1.0.

**Spec:** `docs/specs/2026-11-06-ma16200-study-app-design.md`

## Global Constraints

- Node 24 (present: v24.21.0). Package manager: pnpm. Do not use TypeScript 7.
- No backend. No network calls from the app at runtime. Chen's video and notes URLs are plain links.
- Content ids: lessons `L1`..`L35`, reviews `R-exam1`, `R-exam2`, `R-exam3`, `R-final1`, `R-final2`, `R-final3`; cards `L23-c04`; exams `f2025-e1`, `s2024-final`; questions `f2025-e1-q03`.
- Units, exact strings: `Vectors` (L1-L4), `Applications of Integration` (L5-L10), `Integration Techniques` (L11-L18), `Sequences and Series` (L19-L26), `Power and Taylor Series` (L27-L32), `Polar` (L33-L35). Reviews have `unit: null`.
- Every exam question has exactly five choices labeled A to E.
- Engine code under `src/engine/` imports nothing from `src/ui/` or `src/storage/` implementations; it takes plain data and an injectable `now: Date` and `rng: () => number`.
- Mastery: EWMA alpha 0.3; untested below 3 attempts; weak below 0.7. Selector weights: untested 3, weak 3, else `1 + (1 - score)`. Missed-question recency window: 7 days. Mock exam: 12 questions, excludes the last two mock sessions. Daily new-card cap default 10.
- Markdown with LaTeX everywhere content is text. KaTeX errors render the raw LaTeX in red, never throw.
- The app must build and all tests must pass with any subset of content files present, including no exams and no cards.
- `raw/` is gitignored. `content/` and `public/figures/` are committed.
- Commit after every task with the attribution trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. **New-card cap across local midnight.** A student who reviewed 10 new cards at 23:50 should get 10 more at 00:10. Counting must use the local calendar day of `introducedAt`. Test in Task 6.
2. **Exam timer reaching zero mid-question.** The exam auto-submits; unanswered questions score zero but are not logged as attempts, since silence is not evidence. Test in Task 13.
3. **Page refresh during a timed exam.** Fifty minutes of work must not vanish. In-progress exam state is persisted to `sessionStorage` and restored on mount. Test in Task 13.
4. **Importing a snapshot from a newer schema version.** Must reject with a message naming `version`, leaving existing data untouched. Test in Task 3.
5. **A covered lesson with no eligible questions.** The selector must skip it rather than return nothing or loop. Test in Task 7.

### Task 5: Mastery

**Files:**
- Create: `src/engine/mastery.ts`, `src/engine/mastery.test.ts`

**Interfaces:**
- Consumes: `Attempt` (Task 3), `Question`, `Lesson` (Task 2).
- Produces:
  ```ts
  export interface Mastery { score: number | null; attempts: number }   // score null = untested
  export const MASTERY_ALPHA = 0.3, MIN_ATTEMPTS = 3, WEAK_BELOW = 0.7
  export function lessonMastery(attempts: Attempt[], questionById: Map<string, Question>, lessonIds: string[]): Map<string, Mastery>
  export function unitMastery(lessons: Lesson[], byLesson: Map<string, Mastery>): Map<Unit, Mastery>
  export function isWeak(m: Mastery): boolean          // score !== null && score < 0.7
  ```
  Algorithm for `lessonMastery`: for each lesson, take attempts whose question's `lessonIds` include it, sort ascending by timestamp, `score = first.correct ? 1 : 0`, then `score = 0.3 * (correct ? 1 : 0) + 0.7 * score`. Fewer than 3 attempts gives `score: null`. `unitMastery` averages lessons with non-null score; `attempts` is the sum.

- [ ] **Step 1: Write tests**

- no attempts: `{ score: null, attempts: 0 }`
- two attempts: `score null, attempts 2`
- `[correct, correct, wrong]` in time order: score `0.7` (within 1e-9); `isWeak` false
- `[wrong, wrong, correct]`: score `0.3`; `isWeak` true
- order is by timestamp, not array order: `[wrong@t3, correct@t1, correct@t2]` gives `0.7`
- a question tagged `['L22','L23']` counts toward both lessons
- `unitMastery`: unit with lessons `{0.8, null, 0.6}` gives `0.7` and attempts summed; a unit where all are null gives `null`
